# spine-particle-wallpaper

**用 Spine 骨骼动画 + Unity 式粒子特效，给 Wallpaper Engine 做可交互的桌面壁纸。**

Unity 手游里的 Spine 角色 + 粒子特效 + 触摸动作，搬上桌面并保持手感：多套触摸动作系统、念白语音与字幕气泡、BGM、指针拖尾、画面自适应，外加一套内置设置面板。

[English](./README.md)

> 本仓库衍生自 [spicy-wolf/spine-wallpaper-engine](https://github.com/spicy-wolf/spine-wallpaper-engine)（GPL-3.0），
> 在其「Spine 动画播放器」基础上重构成可交互角色壁纸框架。归属与许可见 [NOTICE.md](./NOTICE.md)。

## 和上游有什么区别？

上游是一个**播放器**：把 Spine 文件丢进 `assets/`，它就在壁纸里循环播放。

本仓库在它的渲染内核之上长成了一套**框架**：

| 能力                                      | 上游 | 本仓库                                                                             |
| ----------------------------------------- | ---- | ---------------------------------------------------------------------------------- |
| 多层场景编排（背景 / 角色 / 粒子 / 前景） | 支持 | 支持，并新增 `particle` 层与分层 z 序                                              |
| 触摸交互与动作调度                        | —    | ✅ 热区、动作互斥与打断闸门                                                        |
| 念白语音 + 字幕气泡                       | —    | ✅ 跟随角色锚点、自动换行、淡入淡出                                                |
| BGM                                       | —    | ✅ 循环播放与音量控制                                                              |
| 暂停 / 恢复                               | —    | ✅ **统一音频总闸**（WE `setPaused` + 页面可见性两路信号）                         |
| 指针拖尾                                  | —    | ✅ 跟随鼠标移动发射                                                                |
| 内置设置面板                              | —    | ✅ 6 个分页（末页「壁纸独立设置」按壁纸声明出现），运行时改配置并持久化            |
| 档案面板 / 免责声明                       | —    | ✅ 档案按当前生效配置列出可能触发的事件 / 触发条件 / 动作 / **特效** / 念白 / 语音 |
| 调试探针                                  | —    | ✅ 独立入口（设置按钮下方）+ HUD 与 CDP 快照接口                                   |

> **设置面板的 6 个分页**：音乐 / 字幕气泡 / 事件触发 / 事件池 / 画面调整 / **壁纸独立设置**
> —— 最后一页是**条件页**：只有壁纸在自己的 `config.json` 里声明了 `wallpaperSettings`
> 才会出现（见下文「壁纸独立设置」），没声明的壁纸**连这个标签按钮都没有**。
>
> **调试不在设置面板里**：它是右上角**设置按钮正下方**的独立入口（2026-10-15 起），
> 点开是一个小面板，含「调试总开关 / HUD 文字 / 鼠标红圈 / 热区框」四项，
> 改完就地「保存并应用」。与设置面板**互斥展开**，字段仍是 `probeEnabled` 那四个。
>
> 小面板下半还有两组**触发按钮**（2026-10-15 新增）：**触发动作**列出骨架全部动画
> （点一下只播动画，不出台词不带语音）；**触发事件**列出全部念白条目（点一下按
> actionId 走完整播放路径：动画 + 字幕 + 语音，含打断闸门）。条目多时不滚动——
> chips 自动换行铺开（WE 不转发滚轮，做滚动等于不可见）。

## 功能一览

- **多层场景**：`texture` / `spine` / `particle` / `video` 四种层，按 `position.z` 排布，全屏适配（`fitAspect`：锁高或锁宽），DPI 自适应（`dpr: "auto"`）。露黑检测是**真实覆盖检测**（逐层投影到屏幕、逐边算缺口），不再是长宽比阈值。
- **触摸交互**：矩形热区 + 动作序列；`touch` / `greet` / `standby` 三类来源有明确的互斥与打断规则。热区在 `config.json` 的 `touch.zones` 里**自定义**（增删改、单区 `enabled`、`priority`），多个区重叠时按 `enabled → priority 降序 → 面积升序 → 数组下标` 裁决出唯一一条（详见 `docx/PLAN_触摸热区自定义与重叠_2026-10-17.md`）。
- **语音与字幕**：字幕气泡跟随角色锚点，语音走独立播放器；两者都接入音频总闸。
- **音频总闸**（`src/audioMaster.ts`）：BGM 与语音不再各自订阅暂停信号，而是登记到同一个总闸统一处理暂停/恢复。语音从暂停处续播。
- **粒子与拖尾**：`ParticleAnimator` 负责场景粒子，`PointerTrail` 负责鼠标拖尾，两者刻意分家。
- **设置面板**：运行时修改并持久化到 WE 属性。
- **调试面板**：入口在设置按钮**正下方**（独立于设置面板），4 个诊断开关，改完重载生效；下半还有「触发动作 / 触发事件」两组 chips，点一下直接播（不走保存）。
- **调试探针**：`__WB_DIALOGUE__` / `__WB_FX__` 快照接口，配合 headless Chrome + CDP 做自动化回归。

## 事件列表与触发规则

「什么情况下角色会说哪句话」全部写在 **`assets/events.jsonc`**（与 `config.json` 同目录）。
一条事件自带**分组标记、条件、动画、粒子、念白、语音**；改完**不用重新构建**，
在 Wallpaper Engine 里重新加载壁纸即可生效。

> **为什么不在 `config.json` 里**：那份文件是构建产物（生成器会整块重写），注释必然被冲掉；
> 而事件需要一段能写清楚"字段是什么、优先级怎么排"的说明。事件文件支持 `//`、`/* */`
> 注释与行尾逗号，还能离线校验（`scripts/validateEvents.ts`）。
> **文件开头就写着完整字段表 + 三条示例** —— 打开就能照着改，不需要翻文档。

```jsonc
{
  "schema": 1,
  "events": [
    {
      "id": "game:64001", "actionId": 64001, "label": "晴日上午问候",
      "on": ["resume"], "kind": "greet",
      "when": { "time": { "start": 5, "end": 12 } },   // 05:00–12:00（start>end = 跨零点）
      "animation": "greet",
      "text": "早上好。", "textTime": 6,
      "voice": "CV/Asuna/Morning_01.ogg"
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `on` | **分组标记**：`touch`（点击热区）/ `standby`（静置）/ `resume`（载入、回到桌面、回到前台）。可写数组。★ **不限制入口**（2026-10-21）—— 能不能被某个入口播到由面板勾的「类别」决定；想锁时机请用 `when.ctx.signal` / `when.ctx.zone`。`on: []` = 永不播放 |
| `kind` | 类别：`touch` / `chat` / `greet`。省略则按 `on[0]` 推 |
| `when` | 条件：`time{start,end}`、`calendar{month,day}`、**`dates["MM-DD" / "YYYY-MM-DD", …]`**（农历节日用它）、`ctx{idleMs,zone,signal}`，可用 `all` / `any` / `not` 组合 |
| `animation` | spine 动画名；不写 = 纯台词事件 |
| `particles` | 本条专用粒子组（`config.meshes[].name`）；不写 = 按动画名回落 |
| `variants` | 整包随机：动作 + 台词 + 语音来自同一包 |
| `pick` | `priority`（同次触发先比档）、`weight`（同档加权；**0 = 只手动触发**）、`group`（互斥）、`cooldownMs`、`quota`、`interrupt` |
| `enabled` | `false` = 作者默认关闭（用户仍可在面板打开） |

**想加一条事件** = 往 `events` 数组里加一个对象；**想删** = 删掉那个对象。
面板里的「事件开关」只能开 / 关（本机），**不改这个文件**。

> ⚠️ 某个入口勾中的类别里如果所有事件都是 `weight: 0`，该入口永远不会自动触发（启动时会打 warn）。
> ⚠️ `pick.priority` 是**全局档位**（不按入口隔离）：高优先级事件会从所有入口抢戏；
> 想让每个入口各播各的，就把它们放在同一档（缺省 0）或用 `when` 分流。

### 语音文件格式：`ogg` / `mp3` / `wav` / `m4a` 混装都能放（2026-10-17）

`subtitle.dialogues[].voice` 只写文件名，**扩展名不再是硬约束**：播放时先原样试
（写 `X.ogg` 就试 `X.ogg`），失败再按 `subtitle.audio.extOrder` 换扩展名重试，
每个候选只试一次。所以解包产物从 ogg 转成 mp3 时，**config 一行都不用改**。

```json
"audio": { "enabled": true, "volume": 1.0, "path": "./assets/voice/",
           "extOrder": ["ogg", "mp3", "wav", "m4a"] }
```

| 情况                  | 行为                                                                    |
| --------------------- | ----------------------------------------------------------------------- |
| `voice` 带扩展名      | 先试它；失败后按 `extOrder` 把**词干**换扩展名重试                      |
| `voice` 不带扩展名    | 直接按 `extOrder` 依次拼（`X.ogg` → `X.mp3` → …）                       |
| 格式明显不支持        | `canPlayType` 判否的**直接跳过**（若全被判否 ⇒ 不信探测、按原顺序实测） |
| 全都找不到            | 静音，**字幕照常显示**；控制台每个文件只 warn 一次                      |
| `extOrder: []`        | 关掉兜底：只试 `voice` 里写的那个扩展名                                 |
| 某词干上次用 mp3 成功 | 下次同词干**先试 mp3**（混装目录里少一次失败重试）                      |

⚠️ 自动播放被拦（`NotAllowedError`）**不会**被当成"格式不对"去换扩展名 —— 那是首次打开
无声的原因，点一下热区即可，与文件本身无关。
⚠️ `m4a` 故意排在最后：WE 的 CEF 对 AAC 支持不稳，放前面会"明明有 ogg、却先撞一条解不了的"。

离线核对目录与 config 是否对得上（不跑壁纸，列出每个格式的数量、同词干多格式冲突、
config 里引用了但目录里没有的语音）：

```bash
npm run voice-manifest                                    # 只报告
npm run voice-manifest -- --write                          # 顺手产出 voice/manifest.json
npx ts-node --transpile-only scripts/voiceManifest.ts <语音目录> <config 路径>
```

### 两页分工：事件触发 / 事件池

内置设置面板把"触发"这件事拆成两页（`id` 是历史值，**不要改** —— 改 id 会打断既有锚点与验证脚本）：

| 页           | `id`       | 管什么                                        | 设置项                                                                               |
| ------------ | ---------- | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| **事件触发** | `sequence` | "**什么时候 / 在哪里**触发" —— 触发条件与规则 | 常驻动作序列与间隔、待机时长、**触摸热区范围改为全屏**、播放动作时点击、问候触发方式 |
| **事件池**   | `touch`    | "触发后**能抽到哪些内容** / **播哪套动画**"   | 前三个入口的类别多选（同构，连排）+ **末尾两行**：点击触摸的事件族、spine 动作族显示 |

> **为什么这样分**：重组前「触摸可触发的事件」在「动作」页，而它的**第二层筛子**（事件族）在「触摸」页
> ⇒ 同一件事被劈成两页。现在"入口 → 取值范围"全在同一页。
> **行序**（2026-10-11 定稿；2026-10-17 末尾加一行）：三个**入口**先列完（待机 / 触摸 / 回到壁纸），
> 再收两层筛子（事件族 → spine 动作族显示）—— 同构的三行不被别的项打断，筛子也不假装成"第四个入口"。

另有两个可在「事件触发」页改的行为开关：

- `touchFeedbackMode` —— 已经有动作在演的时候再点一下：
  **`legacy`**（默认，仅问候/聊天时立即播新的；演触摸动作时点击不响应，= 旧版行为）/
  **`immediate`**（任何情况下都立刻播新的）/ **`queue`**（等当前这条演完自动接上）/
  **`none`**（不做任何反馈）。
- `greetMode` —— 问候取条方式：**`time`**（默认，按系统时间）/ **`random`**（随机）。

### 「事件池」页 · 三个「可触发的事件」多选（`*Kinds`）

**三项同构**的多选，每项决定**那一个入口**能播哪几类事件
（选项都是 `"chat"` / `"greet"` / `"touch"`，即 chat 类 / greet 类 / touch 类）：

| 设置项                 | 字段           | 触发时机                                   | 缺省        |
| ---------------------- | -------------- | ------------------------------------------ | ----------- |
| 长时间待机可触发的事件 | `standbyKinds` | 静置超过「事件触发」页设定的时长           | `["chat"]`  |
| 触摸可触发的事件       | `touchKinds`   | 点中任一热区                               | `["touch"]` |
| 回到壁纸可触发的事件   | `resumeKinds`  | 载入后 / 回到桌面 / 回到前台 / WE 暂停恢复 | `["greet"]` |

三个缺省**刻意各自不同**，合起来 = "升级后行为与改动前逐字相同"。勾了多类时把各类的池
**并成一个大池**随机取一条（池内每条等概率、类别之间按条目数加权）；写成空数组即彻底关掉该入口。
唯一的例外：某个入口**只勾 `greet` 一类**时按 `greetMode` 取条（否则「按系统时间问候」会失效）。

### 「事件池」页 · 两层正交的筛子：事件族（`eventFamilies` + `phases`）与动作族（`actionPhase`）

面板里「事件池」页的最后两行是这两个东西，**它们不是一件事**：

| 面板项               | 字段                   | 管什么                                         | 作用域                                         |
| -------------------- | ---------------------- | ---------------------------------------------- | ---------------------------------------------- |
| **事件族**           | `subtitle.phases`      | 哪些**念白**能被抽到（族级许可）               | **全局**：一项都不勾 ⇒ 所有事件都不触发        |
| **spine 动作族显示** | `subtitle.actionPhase` | 播哪一套**动画名**（`greet` vs `greet_marry`） | **全局**：常驻 / 问候 / 待机 / 点击 / 常驻序列 |

> ★★ **2026-10-17 二次变更**：事件族从"仅点击触摸"改成**对所有入口生效**，
> 字段也从 `touchPhases` 改名为 `phases`（旧键仅作兼容读入）。
> 于是：**只勾「誓约后事件」⇒ 只有那 3 条 `MarryAction` 会触发**（问候/待机都被挡住）；
> **一项都不勾 ⇒ 所有事件都不触发**，档案里没有任何事件行。

#### ★★ 2026-10-17 起：两族制 + 动作族

**为什么改**：游戏侧 `SoulSpineCell.PlayAction` 的口径是
`isOath and MarryActionState ≠ ""` ⇒ 同一条动作、同一条 CV，**只换动画名**
（`GotoIdleState` 也换 `idle_marry`）。原来把这件事实现成"触摸通道再筛一层族"是错位的：
它会连带把婚后的问候/闲聊整类筛掉，而 `idle` 根本不受控。现在拆成两件正交的事：

- **动作族**（`actionPhase`）负责换名 + 决定"属别的动作族的条目能不能进池"；
- **事件族**（`phases`，全局闸门）负责"哪些族允许被触发"——四个入口共用同一道闸门。

同时**取消 `preMarry` 族**（婚前/普通本来就是同一批候选，拆两族只是多一个语义重叠的勾）：
原先标 `preMarry` 的条目一律归 `normal`。

```jsonc
// 誓约皮肤（S8/S6）这样声明；普通皮肤可完全不写（见下面的缺省）
"eventFamilies": [
  { "id": "postMarry", "label": "誓约后事件", "actionLabel": "誓约后",
    "default": true, "matchSuffix": "_marry" },
  { "id": "normal", "label": "普通事件", "default": true, "fallback": true }
],
"phases": ["postMarry", "normal"],   // 事件族（全局闸门；[] = 全关）
"actionPhase": "postMarry",       // 「spine 动作族显示」= 誓约后（缺省）
"actionPhaseBaseLabel": "誓约前"   // 不换名那一档的显示名
```

| 注册表字段    | 必填 | 含义                                                                                                                                                 |
| ------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | ✅   | 事件族 id —— 条目 `phase` 引用它。**自由字符串**                                                                                                     |
| `label`       |      | 面板 / 档案里显示的人话名。缺省回落成 `id`                                                                                                           |
| `actionLabel` |      | 「spine 动作族显示」单选里的**短名**（如「誓约后」）。缺省回落 `label`                                                                               |
| `default`     |      | 面板**缺省勾选**（可标多个；都没标 ⇒ 只勾缺省族）                                                                                                    |
| `fallback`    |      | **缺省族**（唯一）：条目未标族时归入本族；也是"**不换名**"的那一族                                                                                   |
| `matchSuffix` |      | **动作变体后缀**：① 条目没写 `phase` 时用它判族；② `actionPhase` 指向本族时按"原名 + 后缀"换名。★**写了它 ⇒ 本族出现在「spine 动作族显示」的选项里** |
| `keyPrefix`   |      | **按事件键前缀归族**（2026-10-21）：如 `"custom:"` ⇒ 所有 `custom:*` 条目缺省落本族，不必逐条写 `phase`                                            |

**条目 → 事件族**的四段判据（引擎 `dialogue.resolveDialoguePhase`）：
① 条目显式 `phase` 且在注册表里 ⇒ 就是它；② 否则看各族的 `keyPrefix`（事件键前缀，先声明先赢）；
③ 否则按各族的 `matchSuffix` 匹配动画名；④ 都不中 ⇒ 缺省族。

> ★ **前缀排在动画后缀之前**：事件键是**来源声明**（`custom:` = 自建、`game:` = 游戏表出身），
> 比"动画名以 `_marry` 结尾"这种启发式更硬。自定义事件真要归动作族，写显式 `phase` 即可。

#### 2026-10-21 新增：节日族与自定义族

```jsonc
"eventFamilies": [
  { "id": "normal",   "label": "普通事件",   "fallback": true, "default": true },
  { "id": "festival", "label": "节日事件",   "default": true },
  { "id": "custom",   "label": "自定义事件", "default": true, "keyPrefix": "custom:" }
]
```

- **节日类**：情人节 / 元旦 / 春节……条目写 `"phase": "festival"`。★ 农历节日（春节 / 中秋 /
  端午）的公历日期逐年漂移，用 `when.dates` 直接列出来：
  `{"dates": ["2026-02-17", "2027-02-06", "2028-01-26"]}`，每年追加一行。
  引擎**不做农历换算** —— 那是一份要每年校对的数据，错一天就等于过节过错了。
- **自定义类**：所有 `custom:*` 由 `keyPrefix` **自动认领**，不必逐条写 `phase`；于是面板里
  可以一键关掉"用户自建事件"整族，而不影响内置事件。
- 三族都标 `default` ⇒ 面板缺省全勾，行为与"没有族"时逐条一致。
- ⚠️ **存档兼容**：`phases` 会被面板写进 `localStorage`。如果你的存档是在加族之前保存的
  （里面只有 `["normal"]`），新增的两族**不会自动勾上** ⇒ 到「事件池 → 事件族」把三族都点上
  （或点面板底部「恢复默认」，它会连这个存档一起清掉）。此时档案面板会把相关条目标成
  「所属事件族「custom」未勾选 ⇒ 当前不可触发」，不是静默消失。

**换名**（引擎 `dialogue.resolveEntryAnimation`，三分支、显式优先）：
① `DialogueEntry.phaseAnimations[actionPhase]` ⇒ 用它（解决 `chat` → `chat2_marry` 这种
"不是原名加后缀"的个例）；② 原名已以该族后缀结尾 ⇒ 原样；③ 否则 `原名 + 后缀`。
⚠️ 换名**只改动画名**，`actionId` / `text` / `voice` 一律不动 —— 游戏侧 CV 不分誓约前后。

| `subtitle.eventFamilies`                   | 结果                                                                                    |
| ------------------------------------------ | --------------------------------------------------------------------------------------- |
| **没配** / 非数组 / 数组里一个合法项都没有 | 内置缺省 = **只有一族 `normal`** ⇒ 非誓约皮肤既看不到「事件族」行，也看不到「动作族」行 |
| **空数组 `[]`**                            | **本项目没有事件族机制**：两行都不建、不按族筛、不换名                                  |
| 合法数组                                   | 原样归一（丢非法项、按 `id` 去重、保持声明顺序）                                        |

| 设置项               | 字段                   | 缺省                                                 | 说明                                                                               |
| -------------------- | ---------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 触摸热区范围改为全屏 | `touch.fullscreen`     | `false`                                              | ⚠️ 在**「事件触发」页**：打开 ⇒ 忽略 `touch.zones`，整块画面都是热区               |
| 事件族               | `subtitle.phases`      | 注册表的缺省勾选                                     | ⚠️ 在**「事件池」页**（倒数第二行）；**全局**：先按族筛、再按类别随机；`[]` = 全关 |
| spine 动作族显示     | `subtitle.actionPhase` | **第一个带 `matchSuffix` 的族**（誓约工程 ⇒ 誓约后） | ⚠️ 在**「事件池」页**（末行，单选）；`""` = 不换名（誓约前）                       |

> ★ `phases` 的**缺省 = 注册表里标 `default` 的那些**（都没标 ⇒ 缺省族）；写成空数组 =
> **全关**（所有池为空）。**注册表为空 / 无动作族时对应那一行不建**。
> ★ 三个"自动"通道（待机 / 回到壁纸 / 常驻序列）与点击**共用同一套池**、受**同一道族闸门**
> 约束 —— 只勾一族时其余族在四个通道里同时消失，不会出现"待机能播、点击不能播"的劈叉。
> ★ 池成员资格：属**别的动作族**的条目在当前状态下**不进池**（`dialogue.isEntryVisibleInPhase`）
> ⇒ 誓约前 6 条（`TouchFeedback`）/ 誓约后 9 条（+ `MarryAction`），与游戏一致。

#### 誓约工程（S8/S6）的判据（★ 这是**内容分类口径**，不是引擎规则）

判据 = **「婚后这一位会不会换人」**（★ 不是动画名！）：原表 `MarryAction{1,2,3}` **替换**
`TouchFeedback{1,2,3}` —— 婚后触摸位 1/2/3 换播别的动作、4/5/6 原样沿用（全库 26 个 control
结构一致）。2026-10-17 起不再拆 `preMarry`：

| `phase`     | 判据                                                          | 内容（S8/603）        | `animation`（誓约前） |
| ----------- | ------------------------------------------------------------- | --------------------- | --------------------- |
| `postMarry` | 婚后的**替换者**（= 原表 `MarryAction` 组，**仅誓约态存在**） | 63004 / 63005 / 63010 | `SoulActionState`     |
| `normal`    | 其余全部（含原先被换掉的那 3 位）                             | 10 条                 | `SoulActionState`     |

| 动作族         | 触摸池 | 常驻 / 问候 / 待机                            | 依据                                |
| -------------- | ------ | --------------------------------------------- | ----------------------------------- |

| 誓约前（`""`） | **6**  | `idle` / `greet` / `chat`…                    | 只剩 `TouchFeedback` 6 位           |

### 「壁纸独立设置」页 —— 只对本壁纸生效的项

面板标签条**最后一页**，专门收**只对某一张壁纸有意义**的设置项（通用页只留通用项）。
它由**壁纸自己的 `config.json`** 声明：

```json
"ferrisWheel": { "cabinMode": "gravity", "spriteTiltDeg": 15 },
"wallpaperSettings": {
  "label": "盛夏游乐场",
  "items": ["cabinMode"]
}
```

| 字段                      | 含义                                                                      |
| ------------------------- | ------------------------------------------------------------------------- |
| `wallpaperSettings.label` | 页内**分组标题** = 本壁纸的名字（如「盛夏游乐场」）。缺省 `"本壁纸"` 兜底 |
| `wallpaperSettings.items` | 本壁纸声明的独立设置项（数组顺序 = 面板里的行序）                         |

当前唯一可声明的项：

| `items` 取值  | 面板里的项         | 值的唯一来源（★ 不在这里存值） | 为什么算"壁纸独立"                               |
| ------------- | ------------------ | ------------------------------ | ------------------------------------------------ |
| `"cabinMode"` | 「摩天轮轿厢角度」 | `ferrisWheel.cabinMode`        | 只有配了摩天轮粒子组的构图（盛夏游乐场）才有意义 |

> ★★ **不声明 / `items` 为空 / 全是写错的 id ⇒ 面板连这一页（含标签按钮）都不建** ——
> 没有独立设置的壁纸不会多出一个永远空着、或永远无效的页。
> ★ `wallpaperSettings` **只声明"展示什么"**；各项的值仍在自己的正式字段里
> （`cabinMode` → `ferrisWheel.cabinMode`），覆盖层字段名与落盘格式一律不变。
> ★ 本页是 2026-10-11 从「画面调整」页拆出来的（那一页现在只剩「画面对齐基准」与「鼠标粒子拖尾」两项）。

#### ★★ `ferrisWheel.spriteTiltDeg`：轿厢图元**自带**的倾角（缺省 15）

轿厢两个档位的角度都**多算了图元自带的那一份**（远古 bug，2026-10-11 修复）：

| 来源             | 说明                                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **图元自带**     | `FX_cf_chexiang01/02.png` 是美术按**画面重力系**画的 —— 图元自身相对画布就歪着（放大后与**游戏实录**里同一只吊舱对比即见：实录窗格竖直、图元窗格歪） |
| **配置又给一份** | `startRotation` = −15°（`gravity` 档的定义）                                                                                                         |
| **叠加后果**     | `gravity` 渲染成 **−30°**、`game` 也剩 **−15°**（两个档位都多歪 15°）                                                                                |

⇒ 轿厢组的出生朝向 = `cabinMode` 给的角度 **+ `spriteTiltDeg`**（**只对 `cabinGroups` 名单内的组生效**）。
补偿后 `startRotation` 的面值 = 画布坐标下的真实渲染角：`gravity` → 15°、`game` → **0°（窗格竖直，与实录一致）**。

> ⚠️ 换皮肤 / 重导素材后要重新量这个角（09 文档 `04_渲染差异记录.md` §D1 的极点法），别照抄 15。

## 快速开始

```bash
git clone --recurse-submodules https://github.com/awei808/spine-particle-wallpaper.git
cd spine-particle-wallpaper
npm ci
```

> ⚠️ 必须带 `--recurse-submodules`：`packages/threejs-spine-3.8-runtime-es6` 是子模块，漏了会构建失败。

放素材与配置：

1. 把 Spine 三件套（`*.skel` / `*.atlas` / `*.png`）拷进 `public/assets/`
2. 复制示例配置：`cp public/assets/config.example.json public/assets/config.json`
3. 按你的素材改 `config.json` —— 字段说明见 [public/assets/README.zh.md](./public/assets/README.zh.md)

本地预览与构建：

```bash
npm start          # 起 dev server
npm run build      # 产出 dist/bundle.js
```

导入 Wallpaper Engine：把 `dist/` 的内容连同 `assets/` 一起放进一个 WE 工程目录，
再按[官方教程](https://docs.wallpaperengine.io/en/web/first/gettingstarted.html)导入。
