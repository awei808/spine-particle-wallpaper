## 0. 现状盘点：五要素到底散在哪

| 要素 | 现在写在哪 | 形状 | 问题 |
|---|---|---|---|
| **条件** | `subtitle.greeting` / `greet` **数组下标** + `greetingRanges` + `greetMode`；`subtitle.standby`/`chat` + `standbyIdleMs`；`subtitle.touch`（无热区区分）；`*Kinds` 三处多选 | **隐式**：几号位 = 哪个时段；哪个通道 = 谁触发 | 条件不在条目上 ⇒ 改数组顺序 = 条件静默漂移；`Custom-01` 要"只认 `hand` 热区"无法表达 |
| **spine 动作** | `DialogueEntry.animation` + `phaseAnimations` | 已在表内 | 单值，不可随机（本次不做随机） |
| **粒子** | 顶层 `actionEffects[]`，键 = **动画名** | **全局、按动画** | 同一动画被多条事件共用时（S8 的 63007/63008/63013 都是 `touch1`）无法分别配；档案"特效"列靠反查 |
| **念白** | `DialogueEntry.text` | 已在表内 | ✅ |
| **语音** | `DialogueEntry.voice`（仅文件名）+ `subtitle.audio.{path,volume,extOrder}` | 半在表内 | 路径/格式策略属全局，合理；**存在性无从校验**（`file://` 不能 `fetch`） |

**结论**：真正"散"的是**条件**与**粒子**；动作/念白/语音已在表内，缺的是校验。所以单表化 = **把条件与粒子搬进条目**，不是把所有东西塞进一个数组。

## 1. 边界：什么进表，什么留 config

这条不先定，单表化会变成"config 全塞进 `dialogues[]`"的灾难。

| 类别 | 归属 | 判据 |
|---|---|---|
| **逐事件数据**：`id` `channel` `when` `animation` `particles` `text` `voice` `phase` `priority` | **进表**（`subtitle.dialogues[]`） | 换一条事件就要改的值 |
| **环境/全局参数**：`greetingRanges` `standbyIdleMs` `greetingDelayMs` `touch.zones`（几何）`audio.path/volume/extOrder` `eventFamilies`（注册表） `phases` `actionPhase` | **留 config** | 一条事件改它没意义的"世界参数" |
| **池成员/顺序**：`greet` `chat` `touch` `*Kinds` | **留 config，但降级为"兼容壳"** | 它们是"选哪些"的开关，不是"是什么"的定义；条件进表后它们只剩筛选语义 |

> ★ 单表 = **`subtitle.dialogues[]` 继续是唯一真相**，不新建 `events` 表、不新建 `events.json`。
> 理由：`archive` / 投影 / 池 / 调试 API 全部消费它；一旦双表，就必须处处合并，必然出现"档案念 A 表、引擎抽 B 表"（这正是本项目已经踩过的"第二个判据副本"坑）。

## 2. WP-A 单表化

### A0 目标形状

```ts
// 条目 = 一条完整事件；旧字段全部保留为可选 ⇒ 老 config 原样能跑
export type DialogueEntry = {
  id?: string;            // "game:64005" / "custom:goodnight"，缺省由 actionId 派生
  actionId?: number;      // 仅内置事件（溯源/游戏表对齐），自定义事件无
  channel?: TriggerChannel; // 'touch' | 'standby' | 'resume'，缺省由旧字段派生
  when?: Condition;       // 条件 AST（见方案 §3.2），缺省恒真
  particles?: string[];   // 本条专属粒子组；缺省回落 actionEffects[animation]
  phase?: TriggerPhase;   // 已有
  rename?: 'phase' | 'fixed'; // 自定义事件缺省 'fixed'
  // …animation / text / voice / textTime / label / phaseAnimations 保持不变
  priority?: number; weight?: number; cooldownMs?: number; once?: …; interrupt?: …;
};
```

```jsonc
{
  "id": "game:64005",
  "actionId": 64005,
  "channel": "touch",
  "when": { "zone": "hit1" },
  "animation": "touch1",
  "particles": ["fx_touch1_glow"],
  "text": "……",
  "voice": "Asuna_Touch_Hand_05.ogg",
  "phase": "normal"
}
```

### 步骤

| 步 | 内容 | 行为变化 | 验收 |
|---|---|---|---|
| **A1** | 字段进类型 + `normalizeEventTable(dialogues)`（唯一归一入口：补 `id`、`channel`、`when` 缺省、`rename` 缺省、数值夹取） | **无**（字段只读不执行） | `_regress/83`：老 config 归一后逐条等值；`id` 派生正确 |
| **A2** | **迁移脚本**把旧口径写成显式 `channel`/`when`（一次性） | 无（等价改写） | 三工程迁移后 `diff` 只剩新增字段；跑 A1 的等价断言 |
| **A3** | `when` **生效**：`pickChannelEntry` 改为"条件过滤 → 随机"，`pickGreetingEntry` 的**下标时段**改为 `when.timeRange` | 有，但等价（见下） | `_regress/65,67` 全绿 + `_regress/84`（条件矩阵） |
| **A4** | `particles` 生效：`showDialogue` 优先 `entry.particles`，缺省回落 `actionEffects` | 无（`actionEffects` 原样保留） | `_regress/85`：三条通道都走同一解析；旧 config 结果不变 |
| **A5** | 旧字段标注 deprecated：`greeting`/`greet`/`chat`/`standby` 仍读，但每工程启动打一行 `W_LEGACY_CONDITION` | 无 | 三工程各一条 warn，且可关闭（`subtitle.legacyWarnings:false`） |

**A3 的等价性怎么保证**（这是本 WP 最大的风险点）：

| 旧口径 | 迁移后 | 等价条件 |
|---|---|---|
| `greeting: {morning:64001, noon:64002, evening:64003}` + `greetingRanges` | 每条 `when:{timeRange: ranges[slot]}` | `greetMode:'time'` 时按 `timeRange` 过滤 ⇒ 与"下标对位"同一结果（时段互斥且覆盖 24h 时） |
| `greetMode:'random'` | **忽略 `timeRange` 叶子**，其余条件仍生效 | 与旧"随机取 greet 池一条"一致 |
| `standby:64004` / `chat:[…]` + `standbyIdleMs` | `channel:'standby'`, `when:{idleMs: standbyIdleMs}` | 计时器已判过静置 ⇒ 条件恒真（`idleMs` 由调用方保证），结果不变 |
| `touch:[…]` | `channel:'touch'`, `when` 缺省（= 任意热区） | 与"命中任一热区即取池"一致 |

> ⚠️ **不要长期保留"运行期按数组下标派生时段"**：数组一换序，条件就静默换人。
> A2 的迁移脚本是**唯一**允许读下标的时刻，且脚本必须打印"第 N 位 → 哪个时段"供人工核。

### A4 粒子的展开口径

`actionEffects[animation].particles` → 复制到**每条引用该 `animation` 的条目**上。

| 场景 | 处理 |
|---|---|
| 多条事件共用同一动画（S8 `touch1` × 3） | 三条各写同一份 `particles`（显式，可单独改） |
| 某条手工改了 `particles` | 离线校验 `W_FX_DIVERGED`：同动画不同事件的特效不一致 ⇒ 提示"是有意分开的吗" |
| `actionEffects` 仍存在 | 保留为**回落**：条目无 `particles` 时才按动画名查；S6 的 `idleSequence` 裸动画名也靠它 |

## 3. WP-B 合法性校验

### B0 关键约束：校验必须**分层**，不能都塞进 boot

| 层 | 能回答什么 | 为什么 |
|---|---|---|
| **运行时（boot）** | 骨架动画名、热区 id、族 id、粒子组名、条件结构、优先级范围、重复 id | 这些都在**已解析的 config + 骨架**里，纯内存可判 |
| **离线（脚本）** | 语音文件是否存在、粒子贴图是否存在、manifest 是否过期、资源是否被打包 | WE 是 `file://`，`fetch()` 受 CORS 限制 ⇒ **运行期无法遍历目录**（`voiceManifest.ts` 文件头已写明这一点） |

⇒ 运行时校验**不报** `E_VOICE_MISSING`（会误报）；它只报"播放失败"（`voicePlayer` 已有降级）。这条要写进注释，否则后人一定会想"顺手加个语音检查"。

### B1 `src/eventValidate.ts`（纯函数，无副作用）

```ts
export type IssueLevel = 'error' | 'warn';
export type Issue = {

  familyIds: readonly string[];

};

export const validateEvents = (
  events: readonly DialogueEntry[],
  ctx: ValidationContext
```

### B2 错误码（与方案文档一致，补 2 个迁移码）

| code | 级别 | 判据 | 处置 |
|---|---|---|---|
| `E_ID_DUP` | error | 归一后同 `id` 出现两次 | 保留首条，其余标 error |
| `E_ID_INVALID` | error | 不符 `^(game:\d+\|custom:[a-z0-9][a-z0-9_-]{0,39})$` | 该条不播，档案红 |
| `E_ANIM_MISSING` | error | `animation` / `phaseAnimations[actionPhase]` 不在 `ctx.animations` | 该条不播（`addAnimation` 会 **throw**） |
| `E_ZONE_UNKNOWN` | error | `when.zone` 不在 `ctx.zoneIds` | 该条不播（条件永假 ⇒ 等价于不播，但要说明原因） |
| `E_FAMILY_UNKNOWN` | error | `phase` 不在 `ctx.familyIds` | 归缺省族（沿用 `resolveDialoguePhase` ③） |
| `E_COND_INVALID` | error | AST 结构非法 / 取值越界（`month:13`、`start==end`、`chance:2`） | 该条不播 |
| `E_COND_UNREACHABLE` | warn | 静态可判恒假（`{date:{month:2,day:30}}`） | 照登记，档案标"永不触发" |
| `E_EVENT_EMPTY` | error | 无 `animation` 且无 `text` | 该条不播（空事件） |
| `E_PARTICLE_UNKNOWN` | error | `particles[]` 不在 `ctx.particleNames` | 该粒子跳过（条目照播） |
| `W_PRIORITY_RANGE` | warn | `priority` 不在 `0..100` | 夹取 |
| `W_COND_UNKNOWN` | warn | AST 出现未知键 | 该叶子按恒真 |
| `W_FAMILY_NOT_ENABLED` | warn | 所属族未在 `phases` 勾选 | 档案标"当前不可触发" |
| `W_TEXT_EMPTY` | warn | `text` 空 | 纯动作事件（合法） |
| `W_SUFFIX_CONFLICT` | warn | `rename:'phase'` 算出名不存在 | 回落原名 |
| `W_SHADOWED` | warn | 同通道有更高优先级的全条件事件 | 档案标"很难被抽到" |
| `W_LEGACY_CONDITION` | warn | 条目用旧字段派生条件 | 提示迁移（每工程一条，不刷屏） |
| `W_FX_DIVERGED` | warn | 同动画不同事件的 `particles` 不一致 | 仅离线报 |

### B4 门禁语义（"error 不入池"到底怎么实现）

骨架是**异步加载**的，而池在加载前就建好了（`index.ts:835-990`）⇒ 想"建池时剔除"就得重建池。

| 方案 | 做法 | 取舍 |
|---|---|---|
| **B4-a（本次采用）** | 池不动，**消费点过滤**（`playable`） | 改动最小、零重建风险；`touch.ts` 的未知动画闸门已是第二道保险 |
| B4-b（随调度器一起做） | 骨架就绪后 `rebuildPools()` 一次性重建 | 更干净（池里不含废条目），但要等 S4 的单一入口，否则又是"两套建池" |

⇒ 本次走 B4-a，并在 `index.ts` 留 `TODO(S4): 池下沉到骨架就绪后重建`。

## 5. 兼容与回滚

| 变更 | 老 config 结果 | 回滚方式 |
|---|---|---|
| 新增可选字段 | 零影响（全部 undefined） | 删字段即可 |
