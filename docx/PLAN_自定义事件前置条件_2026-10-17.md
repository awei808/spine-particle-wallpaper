## 1. 五要素 → 现状 → 缺口

| 五要素      | 现有实现                                                                                                           | 位置                                                         | 自定义事件缺什么                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 触发条件     | `standbyKinds`/`touchKinds`/`resumeKinds` + `greetingRanges` + `standbyIdleMs` + `touch.zones[]` + `greetMode` | `config.type.ts:1082-1111`、`dialogue.resolveTriggerIntent` | **条件不能组合**：只有"通道 + 全局时段"。要 `2月14日 且 回到桌面`、`23点后 且 在桌面` 这类**多件编排**，必须引入条件 AST |

## 2. 前置条件 A：事件唯一键（`EventKey`）

```ts
/** 事件唯一键。两种命名空间，写进 config 也读得懂 */
export type EventKey = string;
// 内置（游戏表出身的）： "game:64005"      —— 必须带 actionId
// 自定义（用户建的）：   "custom:goodnight" —— 无 actionId
```

| 规则         | 内容                                                                                   |
| ---------- | ------------------------------------------------------------------------------------ |
| 合法性        | `^(game:\d+\|custom:[a-z0-9][a-z0-9_-]{0,39})$`；`custom:` 前缀**保留**，`game:` 段由引擎生成    |
| 兼容         | config / localStorage 里**继续允许写 number**，等价于 `game:<n>`（`normalizeEventKey()` 一个函数兜住） |
| 为什么不用 UUID | 要能写进 `config.json`、能在档案表里一眼读懂、能在回归里写死断言                                              |
| 派生字段       | `actionId?: number` 仅内置事件有；`origin` 不入库，由前缀推导                                        |

### 需要改的调用点（全部是 `number` → `EventKey` 的窄化）

| 文件 / 符号                                      | 现状                          | 改法                                                                  |
| -------------------------------------------- | --------------------------- | ------------------------------------------------------------------- |
| `dialogue.findByActionId(entries, actionId)` | `actionId: number`          | 新增 `findByEventKey(entries, key)`，旧函数保留为薄包装（`_regress/64,65,69` 不动） |
| `dialogue.buildPool(entries, ids: number[])` | `ids: number[]`             | `ids: EventKeyInput[]`（`number \| string`）                          |
| `dialogue.mergeKindPools` 去重键                | `e.actionId + '\|' + phase` | `e.id + '\|' + phase`（`id` 唯一后，族由 `phase` 表达）                       |
| `subtitle.greet/chat/touch: number[]`        | —                           | `EventKeyInput[]`                                                   |
| `__WB_DIALOGUE__.trigger(actionId)`          | 只收 number                   | 收 `EventKeyInput`；**仍然拒绝任意动画名**（后门口径不变）                             |
| `archive.ts` 事件名列                            | `#id` 角标                    | `#custom:xxx`                                                       |
| `idleSequence.items[].actionId`              | number                      | 可写 `eventKey`                                                       |

> ⚠️ 这一步**不改任何行为**，是纯重构 ⇒ 必须先单独落一次、跑满 `_regress/64,65,69,76` 再动字段。这是整个特性的地基。

### 3.2 条件 AST（`Condition`）

**不用 eval、不用字符串表达式**：WE 的 CEF 里 `eval` 既受限又不可审计；AST 可序列化、可 `describe()` 成档案文字、可纯函数单测。

```ts
export type Condition =
  | { all: Condition[] }                       // 与
  | { any: Condition[] }                       // 或
  | { not: Condition }                         // 非
  | { timeRange: DialogueTimeRange }           // 复用现有 {start,end}，支持跨零点
  | { date: { month: number; day: number } }   // 2月14
  | { dateRange: { from: 'MM-DD'; to: 'MM-DD' } } // 节日区间（可跨年）
  | { weekday: number[] }                      // 0=周日
  | { idleMs: number }                         // 静置时长（standby 通道用）
  | { zone: string }                           // 命中热区 id（touch 通道用）
  | { afterResume: 'desktop' | 'any' }         // 区分"回到桌面"与"载入/焦点"
  | { chance: number }                         // 0~1，每次就绪掷一次
  | { notFiredWithin: { id: EventKeyInput; ms: number } }; // 跨事件互斥（A 刚播过则 B 让位）
```

| 设计点    | 决定                                                                                                    | 理由                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 叶子节点集合 | 只做**能被现有数据源满足**的 11 种                                                                                 | `timeRange` 复用 `DialogueTimeRange`；`zone` 复用 `touch.zones[].id`；`idleMs` 复用 `standbyIdleMs` 的语义 |
| 未知键    | **不报错、按"恒真"降级 + `W_COND_UNKNOWN`**                                                                    | 与 `*Kinds` 的容错口径一致（拼错一个词不该把事件关掉），但必须留 warn                                                      |
| 编译     | `compileCondition(cond, ctx) => (now, state) => boolean`；`ctx` 注入 `{ greetingRanges, zones, random }` | 可测：`now` 与 `random` 都能注入 ⇒ 断言可写死                                                                |
| 反序列化   | `describeCondition(cond) => string`（如 `2月14日 ∧ 回到桌面`）                                                 | 档案"触发条件"列直接用它，禁止面板另写一份文案                                                                        |

### 3.3 随机：`variants` 整包覆盖

```ts
export type EventVariant = {
  weight?: number;       // 缺省 1
  animation?: string;    // 缺省继承基准
  particles?: string[];
  text?: string;
  voice?: string;
  textTime?: number;
};
```

| 规则                    | 说明                                                 |
| --------------------- | -------------------------------------------------- |
| 基准字段 = 隐式 variant#0   | 不写 `variants` ⇒ 现有条目**逐字等价**                       |
| 一条 variant 任意字段可缺省    | 缺省 ⇒ 继承基准条目，避免每条都抄一遍                               |

| 动作名一律进骨架存在性校验         | 见 §6 `E_ANIM_MISSING`                              |

## 4. 前置条件 B：事件族怎么扩

### 4.1 现状（已定稿，不要动）

族承担**两种正交职责**，见 `docx/PLAN_誓约态与事件族_2026-10-17.md`：

| 职责             | 字段                                     | 作用域 |
| -------------- | -------------------------------------- | --- |
| 候选闸门（哪些念白能被抽到） | `subtitle.phases`                      | 全局  |
| 动作族（播哪一套动画名）   | `subtitle.actionPhase` + `matchSuffix` | 全局  |

### 4.2 自定义事件需要的三处扩展

| 扩展                    | 内容                                                                                                         | 若不做的后果                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **① 新类别 `'custom'`**  | `TriggerEventKind` 追加 `'custom'`（排在 `TRIGGER_KIND_ORDER` 末尾）；池 = 自定义事件；**三个 `CHANNEL_DEFAULT_KINDS` 都不含它** | 自定义事件没有"哪个入口能触发"的用户开关；只能靠 `when` 暗含，面板说不清                                                  |
| **② 换名豁免 `rename`**   | 自定义事件缺省 `'fixed'`：`resolveEntryAnimation()` 对它直接返回原名                                                       | `actionPhase` 指向 `_marry` 时，`custom` 动画名会被拼成 `xxx_marry` ⇒ 骨架没有 ⇒ `addAnimation` **throw** |
| **③ 族级 `customOnly`** | `EventFamily.customOnly?: boolean`：该族不出现在「spine 动作族显示」、不参与游戏事件判族，只做自定义事件的分类闸门                              | 用户的分类族（`节日`/`彩蛋`）会混进动作族单选，选中后全表换名                                                          |

> ②的实现口径：`resolveEntryAnimation(e)` 增加一句  
> `if (e.rename === 'fixed') return base;`，位置在"取 suffix"**之前** ⇒ 老条目（无 `rename`）行为不变。

### 4.3 判族与可见性（自定义事件天然安全）

| 判据                                 | 自定义事件的结果                                                               |
| ---------------------------------- | ---------------------------------------------------------------------- |
| `resolveDialoguePhase` ①显式 `phase` | ✅ 直接命中                                                                 |
| `isEntryVisibleInPhase`            | 族**无 `matchSuffix`** ⇒ 恒可见（`dialogue.ts:839` 那条分支）⇒ 自定义事件不会因为切动作族而消失   |
| `phases` 闸门                        | 未勾该族 ⇒ 事件不可触发。**必须给 `W_FAMILY_NOT_ENABLED` 告警**，否则"加了事件但永远不播"是最常见的支持问题 |

### 4.4 三层筛子的固定顺序（写死，别各处自己排）

```
① 动作族可见性   isEntryVisibleInPhase       （静态，建池时）
② 事件族闸门     subtitle.phases             （静态，建池时）
③ 通道类别勾选   *Kinds（含 'custom'）        （静态，建池时）
④ 条件/冷却/once                             （动态，每次信号）
⑤ 优先级排序 + 加权随机                        （动态，同 tick）
⑥ 播放闸门       decideAction / decidePlay    （动态，最后一道）
```

> ①~~③ 是"池的成员资格"，④~~⑥ 是"这一次选谁、播不播"。**优先级永远越不过 ①~③** —— 族没勾就是没勾，别让 `priority: 100` 造成"配了却不生效"的错觉。

## 5. 前置条件 C：优先级与调度

### 5.1 为什么现在没有优先级也能用，加了事件就不行

现有三通道**互斥**：点击走 `touch`、静置走 `standby`、恢复走 `resume`，同一时刻基本只有一个信号在响，所以"随机取一条"够用。

自定义事件会打破这个前提：

- `2月14日 + 回到桌面` → 情人节问候
- `23:00-4:00 + 回到桌面` → 晚安问候
- 两条**同时就绪**，随机取 ⇒ 情人节的夜里可能播晚安，语义直接错。

⇒ 必须引入"选谁"的确定性规则。

### 5.2 调度模型（单入口）

新增 `src/eventScheduler.ts`，**取代**现在分散在 `index.ts` 三处的"取池→随机"：

```ts
// 纯函数，便于单测；状态由外部持有
export const selectEvent = (
  ready: EventDef[],                  // 已过 ①~④
  state: SchedulerState,              // lastFiredAt / counters / random
): EventDef | null => {
  if (!ready.length) return null;
  // 1) 优先级降序（缺省 0，全部相等 ⇒ 退化为纯加权随机 = 现状）
  const top = Math.max(...ready.map((e) => e.priority ?? 0));
  const tier = ready.filter((e) => (e.priority ?? 0) === top && (e.weight ?? 1) > 0);
  if (!tier.length) return null;      // 全是 weight:0 ⇒ 只能手动触发
  // 2) 同优先级加权随机（random 可注入）
  const total = tier.reduce((s, e) => s + (e.weight ?? 1), 0);
  let r = state.random() * total;
  for (const e of tier) { r -= e.weight ?? 1; if (r < 0) return e; }
  // 3) 兜底（浮点边界）：取 tier 最后一条，并保证与 tier 顺序无关 —— 排序稳定
  return tier[tier.length - 1];
};
```


| 关键点 | 说明 |
|---|---|
| **缺省全部 priority 0 / weight 1** | ⇒ `selectEvent` 等价于现在的 `pickRandomFromPool` ⇒ **老 config 行为逐字不变**（这条是兼容性承诺） |
| 同一 tick **全局最多播一条** | track 2 只有一个；自动事件本来也不打断（`decideAction` 恒 `reject`） |
| `random` 必须可注入 | 回归要能写死"同优先级下抽到哪条" |
| 冷却剔除在**候选收集阶段** | 不进排序 ⇒ 不会"高优先级但因冷却被抽中又放弃"导致本次空转 |
| 计时用 `setTimeout`/`Date.now`，**不用 rAF** | WE 暂停时 rAF 停、`Date.now()` 继续走（agents.md 不变式 5）。冷却若按帧计时，恢复后会瞬间穿透 |

### 5.3 优先级取值域（建议分档，不要魔法数字）

| 档 | 值 | 典型 | 备注 |
|---|---|---|---|
| 强制 | 100 | 调试 `trigger` / 首次载入 | 内部保留 |
| 用户操作 | 80 | 摸手、戳头 | `channel: 'touch'` |
| 节日/纪念 | 50 | 情人节、生日 | `date` 条件 |
| 时段问候 | 20 | 早安、晚安 | `timeRange` 条件 |
| 日常闲聊 | 10 | 待机闲聊 | `idleMs` |
| 缺省 | 0 | 未标注 | 与现状等价 |

校验域 `0..100`，越界 ⇒ 夹取 + `W_PRIORITY_RANGE`（不拒绝加载）。

### 5.4 打断（`interrupt`）—— 与 `touchFeedbackMode` 的分工

| 候选来源 | 谁说了算 | 说明 |
|---|---|---|
| `channel: 'touch'`（用户点的） | **`touchFeedbackMode` 说了算** | 用户的设置不能被单条事件绕过；`interrupt` 对触摸通道**无效** |
| `channel: 'standby' / 'resume' / 'clock'`（自动） | `interrupt` | 缺省 `'never'` = 现状"自动事件不打断任何东西" |

| `interrupt` | 行为 |
|---|---|
| `'never'`（缺省） | 有动作在演 ⇒ `reject`（与现在逐字一致） |
| `'sameChannel'` | 只在"正在播的也是同一通道"时抢 |
| `'lowerPriority'` | 当前事件 priority **严格大于** 正在播事件 priority 时才抢；否则 `reject` |

实现：新增 `decidePlay(active, candidate, mode)` 薄包装 —— 先按 `interrupt` 判抢占，未通过再原样委托 `decideAction`。**`decideAction` 本体一行不改**（67 条断言守住）。

### 5.5 冷却 / 一次性 / 权重 三者别混

| 字段 | 回答的问题 | 例 |
|---|---|---|
| `cooldownMs` | 两次**之间**至少隔多久 | 摸手 90 秒内不重复 |
| `once` | 一辈子/一天/一次会话只播几次 | 情人节一天一次 |
| `weight: 0` | 这条**要不要参与自动抽** | 只在调试里手动播的彩蛋 |

`once: 'day' | 'ever'` 需持久化 ⇒ 新键 `wb.swe.eventLog.v1`：`{ [id]: { lastAt, count, dayKey } }`；`'session'` 只放内存。冷却状态**不持久化**（重载即清，符合"保存即重载"的现口径）。

### 7.1 单一真相：仍然只有**一张表**

TODO 要求"整合至单个文件/单张表"。落地口径：

```
config.json  subtitle.dialogues[]   ← 唯一真相（保留现名，不新造 events 表）

```

### 7.2 覆盖层：存**增量**，不存整表

```ts
// localStorage: wb.swe.events.v1
type EventOverrides = {
  schema: 1;
  added: EventDef[];                 // 用户新建
  patched: Record<EventKey, Partial<EventDef>>; // 改内置/改自建（一层深合并）
  removed: EventKey[];               // 删内置（墓碑）
};
```

| 决定 | 理由 |
|---|---|
| 不整表拷贝 | 壁纸更新后内置事件会变；整表存 = **用户表被冻结**，新皮肤内容永远进不来 |
| `removed` 用墓碑 | 否则"删了内置事件"下次启动又回来 |
| `patched` 指向已消失的 id | 静默忽略（记 warn），不报错 |
| 合并顺序 | config → `removed` → `patched` → `added`（追加尾部） |
| 生效 | **保存后重载**（沿用 `settingsStore` 现口径），不做热切换 |

### 7.3 面板编辑器的硬约束（这条决定 v1 能做什么）

WE 的 CEF **首帧崩溃于原生表单控件**（agents.md），`settingsPanel.ts` 全是自绘（`_createSlider` 明确"不用 `<input type=range>`"）。而自定义事件要输入**文本**（念白、文件名）。

| 阶段 | 能力 | 取舍 |
|---|---|---|
| **v1（建议先做）** | **零键盘**：新建事件时从既有候选里选 —— `animation` 从骨架动画列表选、`particles` 从 `meshes[].name` 选、`text`/`voice` 从现有念白条目"继承"、`when` 用**条件模板**（时段/日期/热区/静置）+ 数值滑块 | 能覆盖 TODO 三个示例的**全部**场景（都不需要新文本），且无输入法/焦点风险 |
| **v2** | 自绘单行文本输入（隐藏 `<textarea>` + 自绘 caret，或逐字选字盘） | 成本高，先不阻塞 |

> ⇒ **前置条件里必须写明**：v1 的"念白"来自"复制既有条目"，而不是"用户敲一段新台词"。否则工期会低估一个数量级。
