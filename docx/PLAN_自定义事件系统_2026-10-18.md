## 1. 边界：什么进表，什么留 config

这条不先定，单表化会变成"config 全塞进 `dialogues[]`"。

| 类别                                     | 归属                                    | 判据                     |
| -------------------------------------- | ------------------------------------- | ---------------------- |
| **逐事件数据**：`id` `on` `kind` `when` `animation` `particles` `text` `voice` `phase` `pick` | **进表**（`subtitle.dialogues[]`）        | 换一条事件就要改的值             |
| **环境/世界参数**：`greetingRanges` `standbyIdleMs` `greetingDelayMs` `touch.zones` 几何 `audio.*` `eventFamilies` `phases` `actionPhase` | **留 config**                           | 一条事件改它没意义              |
| **用户开关**：`*Kinds`（三类多选）、`subtitle.validate` | **留 config**                           | 决定"要不要这一类"，不定义"是什么"    |
| **旧池成员**：`greeting` `greet` `chat` `standby` `touch` | **迁移后删除**（见 §5）                       | 迁移完成即失效，`*Kinds` 的池改由表派生 |

> ★ 单表 = **`subtitle.dialogues[]` 继续是唯一真相**，不新建 `events` 表、不新建 `events.json`。
> `archive` / 投影 / 池 / 调试 API 全部消费它；一旦双表就要处处合并，必然出现"档案念 A 表、引擎抽 B 表"。

## 2. 数据模型

### 2.1 `EventDef`（= 扩展后的 `DialogueEntry`，全部新字段可选）

```ts
export type EventKey = string;               // "game:64005" | "custom:goodnight"
export type TriggerChannel = 'touch' | 'standby' | 'resume';

export interface EventDef {
  // ── 身份 ──
  id: EventKey;                 // 必填（载入时归一，缺省由 actionId 派生）
  actionId?: number;            // 仅内置事件：与游戏表对齐 / 溯源
  label?: string;               // 档案/面板人话名，缺省 = id
  note?: string;
  enabled?: boolean;            // 缺省 true
  // ── 何时 ──
  on?: TriggerChannel | TriggerChannel[];   // 缺省 ['standby']
  kind?: TriggerEventKind;      // 'chat'|'greet'|'touch'，缺省按 on 推（touch→touch, standby→chat, resume→greet）
  when?: Condition;             // 缺省恒真
  // ── 做什么 ──
  animation?: string;           // 基准动画名（命名不变，沿用现字段）
  particles?: string[];         // 本条专属粒子组名（meshes[].name）
  text?: string;
  voice?: string;               // 可含子目录，可带扩展名
  textTime?: number;
  variants?: EventVariant[];    // 整包随机（§2.3）
  // ── 归属 ──
  phase?: TriggerPhase;         // 事件族（分类族请勿写 matchSuffix）
  // ── 怎么选 ──
  pick?: PickPolicy;            // §2.4
}

export interface PickPolicy {
  priority?: number;            // 0..100，缺省 0，越大越优先
  weight?: number;              // >=0，缺省 1；0 = 不参与自动抽，只能手动 trigger
  group?: string;               // 互斥组：同组同一 tick 至多出一条
  cooldownMs?: number;          // 同一条两次触发的最小间隔，缺省 0
  quota?: { max: number; per: 'session' | 'day' | 'ever' };  // 取代 once
  interrupt?: boolean;          // 缺省 false；**仅自动通道有效**（touch 由 touchFeedbackMode 说了算）
}
```

**为什么 `on` 而不是 `channel`**：一条事件挂多通道是常态（问候既能在开机、也能在回到桌面），单值会逼作者复制两条、再靠"两条必须同步改"的错误约定维持一致。

**为什么 `kind` 还在**：它是**用户开关的轴**（`*Kinds` 三个多选），`when` 不能替代它——"我不想在触摸时听到闲聊"是一个开关，不是一条条件。代价是 1 个字段，收益是 `CHANNEL_DEFAULT_KINDS` 与三组勾选一字不改。

### 2.2 条件 AST：4 类叶子 + 3 个组合子

不用 `eval`、不用字符串表达式：WE 的 CEF 里 `eval` 既受限又不可审计；AST 可序列化、可 `describe()`、可注入时钟与随机做纯函数单测。

```ts
export type Condition =
  | { all: Condition[] }
  | { any: Condition[] }
  | { not: Condition }
  | { time: { start: number; end: number } }        // 小时 0..24，支持跨零点（复用 DialogueTimeRange 语义）
  | { calendar: {                                     // 日历：细到日 / 区间 / 星期
      month?: number; day?: number;                   // 2月14日
      from?: 'MM-DD'; to?: 'MM-DD';                   // 节日区间，可跨年
      weekday?: number[];                             // 0=周日
    } }
  | { ctx: {                                          // 运行上下文（由信号方注入，事件不可改）
      idleMs?: number;                                // 已静置多久（standby 通道）
      zone?: string;                                  // 命中的热区 id（touch 通道）
      signal?: ('boot' | 'visible' | 'focus' | 'resume')[];  // resume 通道的具体来源
    } };
```

| 设计点    | 决定                                                                    | 理由                                                                                     |
| ------ | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 叶子收敛   | 11 → 3 类（`time` / `calendar` / `ctx`）                                  | 旧稿的 `date`/`dateRange`/`weekday` 是同一个日历谓词的三种写法；`idleMs`/`zone`/`afterResume` 是同一个上下文的三个字段 |
| `chance` | **删**                                                                 | 与 `weight` 是同一个"概率性抑制"；两个都留，作者配 `chance:0.5 + weight:3` 时无人能解释结果                            |
| `notFiredWithin` | **删**，改 `pick.group`                                          | 否则条件要读别人的事件日志 ⇒ 破坏纯函数、`describe()` 无法表达、求值顺序变隐含依赖                                        |
| 未知键    | **coerce**：该叶子按恒真 + `E_COND_UNKNOWN`                                    | 与 `*Kinds` 的容错口径一致（拼错一个词不该把事件关掉），但必须留 warn                                                   |
| 编译     | `compileCondition(cond, ctx) => (now, state) => boolean`               | `now` / `random` / `state` 全部可注入 ⇒ 断言可写死                                                     |
| 反序列化   | `describeCondition(cond) => string`（如 `2月14日 ∧ 时段 23:00-04:00`）      | **档案条件列与面板预览只准调它**，禁止另写一份文案（两份文案必然漂移）                                                       |

### 2.3 `variants`：整包随机

```ts
export interface EventVariant {
  weight?: number;      // 缺省 1
  animation?: string;   // 缺省继承基准
  particles?: string[];
  text?: string;
  voice?: string;
  textTime?: number;
}
```

| 规则                        | 说明                                                        |
| ------------------------- | --------------------------------------------------------- |
| 不写 `variants` ⇒ 现有条目**逐字等价** | 基准字段 = 隐式 variant#0                                       |
| 一条 variant 任意字段可缺省         | 缺省继承基准，避免每条都抄一遍                                            |
| **整套抽一次**                 | 动作/粒子/台词/语音一起定 ⇒ 不会出现"打招呼的动作配生气的台词"                      |
| `variants` 非空时基准字段仍参与     | 基准 = 兜底变体（`weight` 缺省 1），不会"配了 variants 后基准失效"              |
| **每个 variant 独立过换名**       | `projectDialoguesToActionPhase`（`dialogue.ts:783-805`）只改 `e.animation`，必须扩到 `variants[].animation`，否则混族时播错或不换名 |
| 配额按**事件**算                 | `quota`/`cooldownMs`/`group` 只看事件，不看是哪个变体被抽中                    |

旧稿说"分散在三处、要新建 `eventScheduler.ts` 取代"——**判断偏了**：`pickChannelEntry` 已经是漏斗雏形，缺的是把 #2/#3/#4 收进来，不是再造一个模块。

### 4.2 四层（顺序写死，别各处自己排）

```
① 权限层   enabled + on(通道) + kind(用户勾选) + phases(事件族)   ← 池成员资格（静态）
② 条件层   when                                                  ← 纯函数，注入 now/ctx
③ 限流层   pick.group / quota / cooldownMs                        ← 状态在 eventLog
④ 竞争层   priority 取最高档 → 同档按 weight 加权随机                ← 注入 random
⑤ 播放闸门 decidePlay → decideAction（本体现有，一行不改）
```

```ts
// 纯函数；状态由外部持有，便于单测
export const selectEvent = (
  ready: readonly EventDef[],        // 已过 ①~③
  rnd: () => number,
): EventDef | null => {
  if (!ready.length) return null;
  const top = Math.max(...ready.map((e) => e.pick?.priority ?? 0));
  const tier = ready.filter((e) => (e.pick?.priority ?? 0) === top && (e.pick?.weight ?? 1) > 0);
  if (!tier.length) return null;                 // 全是 weight:0 ⇒ 只能手动 trigger
  const total = tier.reduce((s, e) => s + (e.pick?.weight ?? 1), 0);
  let r = rnd() * total;
  for (const e of tier) { r -= e.pick?.weight ?? 1; if (r < 0) return e; }
  return tier[tier.length - 1];                  // 浮点边界兜底，与 tier 顺序无关
};
```

| 关键点                     | 说明                                                                          |
| ----------------------- | --------------------------------------------------------------------------- |
| 缺省全 `priority:0 / weight:1` | ⇒ `selectEvent` 等价于现在的 `pickRandomFromPool` ⇒ **老 config 逐字不变**（兼容性承诺）   |
| 同一 tick 全局最多一条           | track 2 只有一个；自动事件默认不打断（`decideAction` 恒 reject）                             |
| 冷却/配额剔除在**收集阶段**        | 不进排序 ⇒ 不会"高优先级但被冷却拦下又放弃"导致本次空转                                              |
| 计时用 `Date.now()`，**不用 rAF** | WE 暂停时 rAF 停、`Date.now()` 继续走（agents.md 不变式 5）。按帧计冷却会在恢复瞬间穿透                 |
| `group` 在同 tick 内生效        | 选中组内一条后，同组其它条目本次直接出局（等价旧稿的 `notFiredWithin`，但不污染条件）                        |

## 6. 合法性校验

### 6.1 分层（运行时能答的 / 只能离线答的）

| 层 | 能回答 | 为什么 |
| --- | --- | --- |
| **运行时（boot 后、骨架就绪）** | 动画名、热区 id、族 id、粒子组名、条件结构、优先级范围、重复 id | 都在已解析的 config + 骨架里，纯内存可判 |
| **离线（脚本）** | 语音文件存在性、粒子贴图存在、manifest 是否过期、资源是否打包 | WE 是 `file://`，`fetch()` 受 CORS 限制 ⇒ **运行期无法遍历目录**（`scripts/voiceManifest.ts` 文件头已写明） |

> ⇒ 运行时**不报** `E_VOICE_MISSING`（会误报），只靠 `voicePlayer` 的降级链。这条要写进代码注释，否则后人一定会"顺手加个语音检查"。

### 6.2 码表（一张表，每条只声明一个处置）

**处置三档**，级别由处置派生（`reject ⇒ error` / `coerce ⇒ warn` / `report ⇒ info`）：

- `reject`：该条**不可播**（不是"不入池"，见 §0 #2）
- `coerce`：修好继续播，并记账
- `report`：照播，只在档案/日志记一笔

| code | 处置 | 判据 | 处置细节 |
| --- | --- | --- | --- |
| `E_ID_INVALID` | reject | 不匹配 `EventKey` 正则 | 丢弃该条 |
| `E_ID_DUP` | reject | 归一后同 `id` 出现两次 | 保留首条 |
| `E_ANIM_MISSING` | reject | 换名**后**的名字不在 `skeletonData.animations`（含 `variants[].animation`） | 不播（`addAnimation` 会 throw） |
| `E_EVENT_EMPTY` | reject | 无 `animation` 且无 `text`（且 variants 全空） | 空事件 |
| `E_ZONE_UNKNOWN` | reject | `when.ctx.zone` 不在 `touch.zones[].id` | 条件永假，说明原因而非静默 |
| `E_COND_INVALID` | reject | AST 结构非法 / 取值越界（`month:13`、`start==end`、`chance` 之类未知叶子以外的类型错误） | 不播 |
| `E_PARTICLES_UNKNOWN` | coerce | `particles[]` 不在 `meshes[].name` | 剔掉该名，事件照播 |
| `E_FAMILY_UNKNOWN` | coerce | `phase` 不在注册表 | 归缺省族（沿用 `resolveDialoguePhase` ③） |
| `E_PRIORITY_RANGE` | coerce | `priority` 不在 `0..100` | 夹取 |
| `E_COND_UNKNOWN` | coerce | AST 出现未知键 | 该叶子恒真 |
| `E_SUFFIX_MISSING` | coerce | 换名后的名字不存在但原名存在 | 退回原名（`resolveIdleAnimation` 已是这个口径，念白对齐它） |
| `E_VOICE_MISSING` | coerce | `voice` 不在 `voice/manifest.json`（**仅离线**；无 manifest 则跳过） | 静音 + 保留字幕 |
| `W_FAMILY_NOT_ENABLED` | report | 所属族未在 `phases` 勾选 | 档案标"当前不可触发"（最常见的支持问题） |
| `W_ORPHAN` | report | 表内条目没有任何 `on` 推导路径可达 | 档案标"不可达" |
| `W_TEXT_EMPTY` | report | `text` 与 `variants[].text` 全空 | 纯动作事件（合法） |
| `W_LEGACY` | report | 条目仍靠旧字段派生条件 | 每工程一条，不刷屏 |
| `W_FX_DIVERGED` | report | 同动画不同事件的 `particles` 不一致 | **仅离线** |

> 删掉的码：`W_SHADOWED`（"同通道有更高优先级全条件事件"是静态启发式，误报多、没人据此改配置）。

## 7. 面板 v1 的硬约束（决定工期）

WE 的 CEF **首帧崩溃于原生表单控件**（agents.md），`settingsPanel.ts` 全自绘（`_createSlider` 明确"不用 `<input type=range>`"）。自定义事件要输入文本，这是最大的成本项。

| 阶段 | 能力 | 取舍 |
| --- | --- | --- |
| **v1（先做）** | **零键盘**：`animation` 从骨架动画表选、`particles` 从 `meshes[].name` 选、`text`/`voice` 从现有条目**继承**、`when` 用**条件模板**（时段/日期/热区/静置）+ 数值滑块 | 覆盖三条 TODO 示例的**全部**场景（都不需要新文本），无输入法/焦点风险 |
| **v2** | 自绘单行文本输入（隐藏 `<textarea>` + 自绘 caret，或逐字选字盘） | 成本高，不阻塞 v1 |

> ⇒ 文档必须写明：v1 的"念白"来自"复制既有条目"，**不是**"用户敲一段新台词"。否则工期低估一个数量级。

### 7.1 存储：存增量，不存整表

```ts
// localStorage: wb.swe.events.v1
type EventOverrides = {
  schema: 1;
  added: EventDef[];                        // 用户新建
  disabled: EventKey[];                     // 用户关掉的（含内置）—— v1 只有这一个"改"
};
```

| 决定 | 理由 |
| --- | --- |
| 不整表拷贝 | 壁纸更新后内置事件会变；整表存 = 用户表被冻结，新内容永远进不来 |
| v1 不做 `patched` / `removed` | 合并语义 + 墓碑恢复 + "指向已消失 id"三条规则的成本，远超它解决的场景；`disabled` 覆盖 90% |
| 合并顺序 | config → `disabled` → `added`（追加尾部） |
| 生效 | **保存后重载**（沿用 `settingsStore` 现口径），不做热切换 |

## 9. 多格式语音（已完成，保留落地记录）

现状：`voicePlayer.play(file)` 直接 `basePath + file`，单元素、无探测、失败静默。

| 步骤 | 规则 | 落地位置 |
| --- | --- | --- |
| ① 原样尝试 | `voice` 带扩展名就用它（`.ogg/.mp3/.wav/.m4a`） | `voicePlayer.buildVoiceCandidates` 第一个候选 |
| ② 扩展名兜底 | 失败时按 `subtitle.audio.extOrder` 换扩展名重试，每文件只降级一次；`[]` = 显式关闭 | 同上 + `normalizeExtOrder` |
| ③ 能力探测 | `new Audio().canPlayType()` 按实例缓存；全判否 ⇒ fail-safe 按原顺序实测 | `createVoicePlayer` 内 `canPlay` |
| ④ 失败呈现 | **保留字幕**；每个词干只 warn 一次 | `warnMissingOnce` / `resolvedUrl()` |
| ⑤ 清单 | `npm run voice-manifest`（`scripts/voiceManifest.ts`），`--write` 产出 `voice/manifest.json` | 供 §6.4 离线校验 |

两条踩过的坑（已写进代码注释）：

1. **`NotAllowedError` / `AbortError` 绝不触发降级**——前者是自动播放拦截、后者是我们自己 `stop()`。当成"格式不对"去换扩展名，一次被拒会连试 4 个文件、刷 4 条日志，症状与"文件不存在"完全混淆。
2. **降级链是异步的 ⇒ 必须有代际号**（`generation` + `token`）。连点两下时，上一条迟到的失败不得改写正在播的 `src`；`stop()` 之后迟到的 `error` 也不得复活降级。`_regress/82` 的 J/K 段钉住这两条。

**真机抽样（2026-10-17，headless Chrome，`--autoplay-policy=no-user-gesture-required`）**：把 `64005` 的 `voice` 改成不存在的 `.mp3`，触发后读 `__WB_DIALOGUE__.voice`：`file=Asuna_Touch_Hand_02.mp3` / `resolved=...ogg` / `playing=true` ⇒ 兜底链在真实解码路径上生效。同时测到 `canPlayType`：ogg/mp3/m4a/aac/flac = `probably`，wav/webm = `maybe`（**所以"非空即算能播"的口径是必要的**，按 `''` 才算不支持）。

**仍未做**：完整四格式矩阵（各一条真音频，**尤其 WE 的 CEF 里的 m4a** —— Chrome 能解码不代表 CEF 能，编译开关不同）。`extOrder` 缺省不把 `m4a` 放前面，直到有实测。

## 12. 明确不做

| 不做 | 理由 |
| --- | --- |
| 表达式 `eval` / 脚本条件 | WE 内不可审计、不可测；AST 足够 |
| 用户自定义粒子系统 / 新骨架动画 | 只**引用**已有 `meshes[].name` 与 `skeletonData.animations` |
| 热切换（改完立即生效） | 与现口径一致：保存 → 重载 |
| 按事件独立音量 / BGM 联动 | `audioMaster` 是唯一暂停/音量总闸（不变式 1），加旁路必炸 |
| 优先级决定"能否播" | 优先级只回答"选谁"，`decideAction` 回答"能不能播"，两者正交 |
| `interrupt` 绕过 `touchFeedbackMode` | 用户设置优先于单条事件 |
| v1 的自由文本输入 | 见 §7，零键盘先落地 |
