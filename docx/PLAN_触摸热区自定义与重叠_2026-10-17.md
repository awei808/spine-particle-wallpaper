## 1. 现状 → 缺口 → 取证

| 项       | 改动前                                                         | 缺口                                              |
| -------- | -------------------------------------------------------------- | ------------------------------------------------- |
| 热区来源 | `config.touch.zones`（归一化矩形），另有 `fullscreen` 一个开关 | 用户侧**没有任何**增删改能力                      |
| 命中判定 | `hitTestZones`（`src/touch.ts`）：按数组顺序**先命中先返回**   | 重叠处谁吃掉点击取决于数组顺序 ⇒ 不可预测、不可调 |
| 可观测性 | 覆盖层只高亮一条；探针只显示 `lastHitZone`                     | 重叠时看不出"为什么是它"                          |
| 校验     | 无。id 撞车 / 坐标写反 ⇒ 静默"点了没反应"                      | 自定义热区后这类错误必然出现                      |

### 取证 1：多热区且重叠**真实存在**（不是假想）

皮肤热区普查总表（`_work_全皮肤热区扫描/全皮肤触摸热区总表.csv`，118 个皮肤）：

| 热区数 | 皮肤数 |
| ------ | ------ |
| 1      | 106    |
| 2      | 4      |
| 3      | 3      |
| 4      | 4      |

多热区的 11 个皮肤里，区与区**互相重叠**（小区域被大区域包住）：

| 皮肤                         | 区（解包世界坐标）                                                                             | 关系                    |
| ---------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------- |
| `tsukinomiyo_s3`             | `base[-8008,-5082,3331,6361]` / `touch2[-1431,-672,2931,1892]` / `greet[-2883,3282,1479,5845]` | `base` 把另两块整块包住 |
| `silenus_s4`                 | `base` / `touch1` / `touch2` / `greet`                                                         | 四块两两相交            |
| `andrea_s4` / `philodoxy_s3` | `base` + `_chat`                                                                               | 部分相交                |

⇒ 旧口径下这些皮肤"点到 chat 区却走了 base"完全取决于 CSV 的导出顺序 —— 不可接受。

### 取证 2：本工程（Asuna S9）只有 1 个区

`public/assets/config.json` 的 `touch.zones` 只有 `hit1`（`u[-2.609,1.590] v[-4.197,3.089]`，
远超视口的整屏兜底区）⇒ **本工程不在"重叠"这一格里**，所以 §5 的零回归承诺可证。

### 取证 3：坐标系方向是坑

解包侧是 Unity UI 的 RectTransform（**y 轴向上**），视口坐标 **y 轴向下**。
换算漏翻转 ⇒ 整片矩形端点反向（`v0 > v1`）⇒ 旧口径下命中判定恒假（点了永远没反应，无报错）。
⇒ `normalizeZones` 自动交换 + 留 `W_ZONE_FLIPPED` 告警。

## 2. 热区自定义：字段

落点唯一：`config.json → touch.zones[]`（`TouchZoneConfig`）。全字段表：

| 字段          | 类型    | 缺省     | 作用                                                                       |
| ------------- | ------- | -------- | -------------------------------------------------------------------------- |
| `id`          | string  | **必填** | 稳定键：覆盖层高亮、探针读数、将来的 `when.zone` 都引用它 ⇒ **唯一且非空** |
| `label`       | string  | —        | 覆盖层标注的人话名                                                         |
| `u0 v0 u1 v1` | number  | **必填** | 归一化视口矩形（0~1，原点左上，与 `clientX/clientY` 同向）                 |
| `enabled`     | boolean | `true`   | 单区开关：`false` ⇒ 不参与判定（调试框仍画，标「关」）                     |
| `priority`    | number  | `0`      | 重叠裁决优先级，越大越优先（非有限数 ⇒ 归 0 + 告警）                       |

### 怎么拿到坐标（开发者流程）

1. `touch.showZones = true`（或调试面板「显示触摸热区框」）；
2. `probe.hud = true` ⇒ 左上角 HUD 直接读鼠标归一化坐标；
3. 照着画面读两个角点，写进 `touch.zones`。

> ⚠️ 热区是**屏幕空间**（解包侧就是 UI 层 RectTransform），**不随角色动画移动**。
> 想要"跟着手走"的热区 ⇒ 需要骨骼绑定，那是另一件事，本轮不做（见 §9）。

### 与 `fullscreen` 的关系

`touch.fullscreen = true` ⇒ **整张 `zones` 被忽略**，只剩一块 `fullscreen` 区
⇒ 自定义热区全部失效，且 `when.zone` 只能引用 `fullscreen` 这一个 id。
⇒ 想玩分区就必须关掉它（已写进 `TouchConfig.fullscreen` 的注释）。

## 3. 重叠裁决（`resolve`）

多个区同时命中时，按下列顺序裁决出**唯一**一条：

```
① enabled !== false      （过滤：停用的区不参与）
② priority 降序           （显式声明 > 隐式推断）
③ 面积 升序              （小的更具体 —— base 是整屏兜底、touch2 是局部，正是解包的本意）
④ 数组下标 升序           （兜底：保证全序，不存在"并列随机"）
```

| 设计点                               | 说明                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------- | ------- | ------------------ |
| 为什么面积升序                       | 解包数据里"局部语义区"（`_touch1` / `_chat`）总是被"整屏 base"包住；小 = 更具体，与人的直觉一致 |
| 为什么 priority 压过面积             | 用户显式声明的意图优先于启发式。想让"手"压过"身体" ⇒ 给 `hand` 一个 `priority: 10`              |
| 为什么第四条留数组下标               | 保证**全序** ⇒ 回归能写死断言，不会出现"两条一样、看运气"                                       |
| 面积用**归一化原值**（不裁剪到视口） | 与视口尺寸无关 ⇒ 不同分辨率下裁决结果稳定                                                       |
| 面积相等判据 `                       | Δ                                                                                               | < 1e-9` | 浮点不能直接 `===` |
| 端点**含**（`u0 <= u <= u1`）        | 与改动前逐字一致 ⇒ 全屏区在画面边缘也命中                                                       |

### 命中结果：`ZoneHit`

```ts
type ZoneHit = {
  zone: TouchZone | null; // 赢家（null = 没命中任何区）
  candidates: TouchZone[]; // 全部命中，已按裁决序排好 ⇒ candidates[0] === zone
};
```

候选全集只给**覆盖层与探针**用，不进播放逻辑（播放只认赢家）。

## 4. 归一与校验（`normalizeZones`）

**宽容**：热区来自解包换算，坐标越界、方向写反是家常便饭；一条坏数据不该让整张表失效
（`zones` 为空 ⇒ 触摸被整体禁用，代价太大）。⇒ 只有"身份"与"几何是不是数"是硬错误。

| code                 | 级别  | 判据                              | 处置                                   |
| -------------------- | ----- | --------------------------------- | -------------------------------------- |
| `E_ZONES_NOT_ARRAY`  | error | `touch.zones` 不是数组            | 空表（`undefined` 不告警，那是"没配"） |
| `E_ZONE_ID_MISSING`  | error | `id` 不是非空字符串 / 项不是对象  | 丢弃该区                               |
| `E_ZONE_ID_DUP`      | error | `id` 与前面某条重复               | **保留第一条**，后续丢弃               |
| `E_ZONE_GEOM`        | error | `u0/v0/u1/v1` 有非有限数 / 缺字段 | 丢弃该区                               |
| `W_ZONE_FLIPPED`     | warn  | `u0 > u1` 或 `v0 > v1`            | **自动交换** + 提醒核对 y 轴翻转       |
| `W_ZONE_DEGENERATE`  | warn  | 宽或高为 0                        | 保留（几乎点不中）                     |
| `W_ZONE_OUT_OF_VIEW` | warn  | 整块落在视口外                    | 保留（永远不会被命中）                 |
| `W_ZONE_PRIORITY`    | warn  | `priority` 非有限数               | 按 0 处理                              |

装配期（`index.ts`）把 issues 逐条打到控制台：`[touch.zones] <id> [<code>] <message>`。

## 5. 零回归边界（改了什么、没改什么）

| 场景                     | 与旧口径                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| 单区（含越界大区）       | **逐点相同**                                                      |
| 互不重叠的多区           | **逐点相同**                                                      |
| **多区重叠**             | **只在这一格不同** —— 由"数组靠前的赢"变成"更具体/更高优先级的赢" |
| 本工程真实 `config.json` | **逐点相同**（只有 1 个区）                                       |

回归里用 11×11 网格（121 点，含 0/1 边界）拿改动前的旧实现逐点对照：
`_regress/77` 的 C1/C2/C4 断言 `diff === 0`，C3 断言"重叠处差异数 = 9（0.4~0.6 的 3×3）"
⇒ 既证明没改坏、也证明规则真的生效了。

> ⚠️ **唯一的兼容代价**：既有的**多热区且重叠**工程（本仓库没有，但用户手上别的皮肤工程可能有）
> 行为会静默改变。这是用户 2026-10-17 明确接受的拍板（"直接改成 smart 为默认"）。

## 7. 给 S3/S4（`when.zone`）的接口约定

本轮只铺路，不绑事件。给后续自定义事件留下的契约：

| 约定         | 内容                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 引用键       | `when.zone` = `touch.zones[].id`（**归一化后的** id，已保证唯一非空）         |
| 命中来源     | 点击事件 ⇒ `ZoneHit.zone.id`；调度器拿它去匹配 `{ zone: 'hand' }` 条件        |
| 未命中       | `zone === null` ⇒ 不触发任何 `zone` 条件事件                                  |
| `fullscreen` | 打开时全表失效 ⇒ `when.zone` 只能写 `"fullscreen"`；校验应报 `E_ZONE_UNKNOWN` |
| 校验时机     | 事件校验（S5）查同一张 `zones` 表 ⇒ `E_ZONE_UNKNOWN`（方案 §6.2 已列）        |
| 不做         | 热区上直接写 `animation` / 事件编号（两套绑定口径会打架）                     |

## 9. 明确不做

| 不做                             | 理由                                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| 可视化框选编辑器（拖拽/滑块）    | 用户拍板：配置项即可，开发者用                                                       |
| 圆形 / 多边形热区                | 解包侧只有矩形（`SoulSpineHitArea` 是 RectTransform），无第二形状 ⇒ 不提前造抽象     |
| 热区 → 动作/念白绑定             | 留给 `when.zone`（结论 C）                                                           |
| 骨骼绑定（热区跟着手走）         | 解包侧就是屏幕空间 UI 层；跟随骨骼要每帧算骨骼屏幕投影，且角色动作幅度大时热区会乱跳 |
| 覆盖层（localStorage）持久化热区 | 没有 UI 写入路径 ⇒ 加了就是死代码；等面板编辑器那一轮一起做                          |
| WE 属性面板暴露热区              | 现有 5 项已固定，热区是开发者配置项                                                  |
