## 1. 用户口径（定稿）

### 第一轮（当日下午）

1. **事件族去掉「誓约前」**：原先标 `preMarry` 的条目归入「普通事件」。

### 第二轮（当晚）—— 事件族改为**全局闸门**

## 2. 字段（`config.subtitle`）

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `eventFamilies[].matchSuffix` | string | — | 语义**升级**：既是"条目判族"的兜底判据，也是"该族的**动作变体后缀**"。★写了它 ⇒ 该族出现在单选里 |
| `eventFamilies[].actionLabel` | string | `label` | 单选里的短名（chips 行仍用 `label`） |
| `phases` | `TriggerPhase[]` | 注册表 `defaultIds` | **全局事件族闸门**（第二轮新增）。`[]` = 全关 ⇒ 所有池空；旧键 `touchPhases` 仅在新键缺席时读 |
| `actionPhase` | `TriggerPhase` | **第一个带 `matchSuffix` 的族** | 当前显示的动作族；`""` = 不换名（誓约前）。❗`""` 是**显式值**，与"没配"不同 |
| `actionPhaseBaseLabel` | string | `默认` | 单选里"不换名"那一档的显示名（誓约工程写「誓约前」） |
| `dialogues[].phaseAnimations` | `{ [族id]: 动画名 }` | — | 该族下的动画名**覆盖**（解决 `chat` → `chat2_marry` 这种非后规范例） |
| `dialogues[].animation` | string | — | 一律写**誓约前**的动画名 |

引擎里**没有任何族名字面量**（`grep` 断言见 `_regress/76` 的 H 段）。

## 3. 行为矩阵

| 通道 | 誓约前（`actionPhase: ""`） | 誓约后（`actionPhase: "postMarry"`） |
|---|---|---|
| 常驻 idle | `idle` | `idle_marry`（骨架确有该动画才换，否则保持 + 日志） |
| 问候 | `greet` / `greet` / `touch2` | `greet_marry` / `greet_marry` / `touch2_marry` |
| 待机闲聊 | `chat` | `chat2_marry`（显式映射） |
| 点击触摸 | **6 条**（`TouchFeedback`） | **9 条**（+`MarryAction`） |
| 常驻序列 | 原名 | 投影后 |
| 字幕 / 语音 / actionId | **不变** | **不变**（游戏侧 CV 不分誓约前后） |
| 动作特效 | 按当前动画名查 `actionEffects` | 同左（`touch1_marry` / `chat_marry` 已绑） |
| **事件族闸门** | `phases` 勾中的族 | 同左（两族全勾 = 全通；只勾一族 = 其余族在**四个通道**同时消失） |

两层闸门**正交**，不要合并（**AND**）：

- `actionPhase`（动作族）：全局换名 + **池成员资格**（属别的动作族的条目不进池）；
- `phases`（事件族）：全局许可 —— **四个入口共用同一套池**，只勾一族时其余族在待机 /
  点击 / 回到壁纸 / 常驻序列里**同时**消失。
