## 0. 结论

**根因只有一条**：`DialogueEntry.actionId` 在 2026-10-18 起变成**可选**
（自定义事件没有游戏侧 actionId），但一批消费方仍把 `actionId` 当成"唯一凭据"。
凡是"按 actionId 定位/显示事件"的路径，遇到自定义事件就退化成 `undefined` / `NaN`。

| # | 问题 | 严重度 | 现状 |

## 1. P0-1 调试面板「触发事件」（用户报告的那条）

### 1.1 调用链

```
index.ts:2412   events: activeDialogues.map((d) => ({ actionId: d.actionId, label: d.label, animation: d.animation }))
settingsPanel.ts:2639-2645
                options.events.map((e) => ({ key: String(e.actionId), text: String(e.actionId), hint: [...] }))
settingsPanel.ts:2647
                (it) => options.onTriggerEvent ? options.onTriggerEvent(Number(it.key)) : false
index.ts:2402   phasedDialogues.find((it) => it.actionId === actionId)
```

三处都假设 `actionId` 存在：

| 环节 | 自定义事件实际值 | 后果 |
|---|---|---|
| `DebugEventItem.actionId: number`（settingsPanel.ts:139） | `undefined`（类型上就写死了必填） | — |
| chip 文案 `String(e.actionId)` | `"undefined"` | 面板显示 undefined |
| chip DOM id `wb-debug-ev-<key>` | 两条自定义事件**同为** `wb-debug-ev-undefined` | id 冲突（回归脚本按 id 反查会拿到第一条） |
| chip title `[e.label, '动画:'+e.animation]` | `label` 也没有（自定义事件用的是 `displayName`） | 悬停只剩"动画:touch1"，看不到"牵着手也不错" |
| `onTriggerEvent(Number("undefined"))` | `NaN` | `actionId === NaN` 恒假 ⇒ 返回 false ⇒ 点了不播 |

### 1.2 实测证据

无头 Chrome 加载 `dist/index.html` 后 dump DOM，调试面板的 chip：

```
id="wb-debug-ev-64005"  title="时装-盛夏游乐场-触碰1 ｜ 动画:touch1"  >64005
id="wb-debug-ev-undefined" title="动画:touch1"                       >undefined
id="wb-debug-ev-undefined" title="动画:greet"                        >undefined
```

`_regress/92_诊断_自定义事件兼容.ts` 段 B/C 输出：

```
chip 总数 = 12 · 文案为 "undefined" 的 chip = 2
这些 chip 的 DOM id = ["wb-debug-ev-undefined","wb-debug-ev-undefined"]
Number("undefined") = NaN ⇒ findById(NaN) === null
```

### 1.3 建议修法（最小改动，三处）

1. `DebugEventItem` 把"凭据"从 `actionId` 换成 `EventKey`（可选同时保留 actionId 仅作显示）：

```ts
export type DebugEventItem = {
  /** 触发的唯一凭据（`game:64005` / `custom:hold-hand`） */
  key: string;
  /** 显示名：`displayName || label || key` */
  name: string;
  actionId?: number;   // 仅显示（可选）
  animation?: string;
};
```

2. `index.ts:2412` 改成 `{ key: eventKeyOf(d), name: d.displayName || d.label || eventKeyOf(d), animation: d.animation }`，
   并把 `onTriggerEvent: (actionId) => ...` 改成接收 `EventKeyInput`，内部 `findByEventKey(phasedDialogues, key)`
   —— 与 `__WB_DIALOGUE__.trigger`（index.ts:2055）走同一条查表路径，不新增第二判据。

3. `settingsPanel.ts:2639` 用 `key` 作 chip 的 `key/domId`（复用同文件 2256 行的 `domKey()` 去掉 `:`），
   `text` 用 `name`，`hint` 里带 `key`。注意 `domKey` 已在 `createSettingsPanel` 函数作用域内，可直接用。

## 2. P1-1 常驻序列闸门（潜伏，影响比 P0 更广）

`index.ts:1808`：

```ts
isActionAllowed: (id) => phasedDialogues.some((d) => d.actionId === id),
```

而 `idleSequence.ts:187-194` 传进来的 `id` 是**归一后的字符串键**：

```ts
const key = normalizeEventKey(keyRaw);          // 64005 → 'game:64005'
if (options.isActionAllowed && !options.isActionAllowed(key)) { ...跳过该项... }
```

`number === 'game:64005'` 恒假 ⇒ **任何写了 `actionId` 或 `key` 的序列项都会被当成
"所属事件族未勾选"整项跳过**（不是退化成只播动画，是整项消失）。自定义事件、内置事件一视同仁。

单测复现（`_regress/92` 段 D，用的是真实 `resolveSequence`）：

```
[idleSequence] items[0] 的 game:64005 所属事件族未勾选 ⇒ 跳过该项
[idleSequence] items[1] 的 custom:hold-hand 所属事件族未勾选 ⇒ 跳过该项
[idleSequence] items[2] 的 game:64005 所属事件族未勾选 ⇒ 跳过该项
结果 = ["chat"]   ← 只剩裸动画名那条
```

为什么没人发现：本工程 `idleSequence.enabled=false`、`items=[]`（`public/assets/config.json`），
`_regress` 里也没有任何脚本覆盖 `isActionAllowed`。

**修法**：`isActionAllowed: (id) => phasedDialogues.some((d) => eventKeyOf(d) === normalizeEventKey(id))`
（`eventKeyOf` / `normalizeEventKey` 都已 import 或可按需加）。

## 3. P1-2 档案：自定义事件被列两遍

`archive.ts` 的表格里，一条自定义事件会出现两次：

- 一次由通道枚举（`pushChannel` / 点击触摸循环，`archive.ts:617-618` 的 `entriesOf` 已按**池**枚举，
  池由事件表派生 ⇒ 自定义事件自动入选）；
- 再一次由 2026-10-18 加的「⑥ 自定义事件」段（`archive.ts:781-800`，判据是
  `key.startsWith('custom:') && !legacyKeys.includes(key)`）。

实测（`data-wb-archive-row` 逐行）：

```
4  | 回到壁纸 · greet类 · 追加 #4/4   | 载入 / 页面重新可见 / … · 2月14日     ← custom:valentine-greet
12 | 点击触摸 · 仅手动                | 点击角色热区 · 池 #—/6（touch类）      ← custom:hold-hand
13 | 自定义 #1 · 牵着手也不错          | 点击 · 恒真                          ← 同一条，第二次
14 | 自定义 #2 · 情人节问候            | 回到壁纸 · 2月14日                    ← 同一条，第二次
```

成因是时间差：⑥ 段是在"通道枚举走旧 id 数组"时加的（那时自定义事件确实不会出现在通道行里）；
2026-10-18 晚 `pushChannel` 改成"池 + `on` 枚举"后，⑥ 段的必要性就只剩"不可达 / 通道不可用时仍可见"。

**修法（二选一）**：

- 推荐：通道枚举时收集已输出的键集合，⑥ 段只列**没被上面任何一行输出过**的自定义事件
  （标题可写「自定义事件（未出现在上方通道）」）；
- 或者：删掉 ⑥ 段，改为在通道行角标上体现 `custom:`（但会丢掉 `displayName` 的展示位置，不推荐）。

另：⑥ 段的数据源是 `st.dialogues`（= 投影 + 存在性过滤后，**未过事件族闸门**），
而通道行用的是过了闸门的 `pools`。⇒ 闸门关掉某族时，⑥ 段仍会把那条列出来，且不带任何提示。

## 4. P1-3 档案忽略 `enabled`（事件开关）

- 运行时：`eventScheduler.collectCandidates`（`eventScheduler.ts:355`）第一层就 `if (e.enabled === false) return;`
- 档案：`archive.ts` 里**零处**读 `enabled`（`pools` 只看 `kind` / `channelsOf`）。

⇒ 用户在「事件开关」页关掉一条后，档案的
「池内随机 1 条（共 N 条）」「池 #k/N」「点击触摸 #k」里仍然算它。
这正是 PLAN 反复强调的"档案不能替引擎撒谎"。

**修法**：`archive.resolveState` 建 `pools` 时加 `e.enabled !== false` 过滤（与 `collectCandidates` 同判据），
并在 `buildNotes` 补一句「另有 N 条被本机事件开关关闭」——只剔除不说明会让人以为事件丢了。

## 5. P2 级（会造成数据丢失或工具静默失效）

### 5.1 常驻序列面板不认 `{key}`，保存即丢

- `settingsStore.stringifyItem`（`:699-713`）只认 `string` / `{animation}` / `{actionId}`；
  `{key:'custom:xxx'}` ⇒ `''` ⇒ 被 `filter(s => !!s)` 丢掉（`:757-759`）。
- `settingsPanel` 保存时无条件下发 `idleSequenceItems`（`:3213`），而 `buildOverrides` 会整表替换
  `idleSequence.items`（`settingsStore.ts:625`）。

⇒ 只要用户在设置面板点一次「保存并应用」，config 里所有 `{key}` / `{actionId}` 形式的序列项
就被"裸动画名数组"覆盖掉（不可恢复，除非有备份）。`idleSequence.resolveSequence` 其实**支持** `key`
（`idleSequence.ts:184-203`），只是面板这一层不认。

**修法**：`stringifyItem` 增加 `if (typeof obj.key === 'string') return obj.key;`；
并在 `applyOverrides` 写 `idleSequence.items` 前，把"对象项"原样保留（或在面板上明确禁止编辑含对象项的序列）。

### 5.2 `scripts/voiceManifest.ts` 已失效

`scripts/voiceManifest.ts:110-111` 仍读 `cfg.subtitle.dialogues`；2026-10-19 起事件只存在
`assets/events.jsonc`，`public/assets/config.json` 里连 `dialogues` 键都没有 ⇒ `npm run voice-manifest`
会"检查 0 条语音"并静默通过（最坏的一种通过）。

**修法**：改用 `parseEventsFile + normalizeEventTable`（与 `scripts/validateEvents.ts` 同一路径）。

### 5.3 调试 chip 没有 ✓/× 回显

`settingsPanel.ts:239-244` 的注释承诺"面板据此回显 ✓ / ×，不猜"，但 `makeChipGroup`
（`:2596-2601`）把 `onClick(it)` 的返回值直接丢掉，只做"变白 3 秒"。

⇒ 即使 P0 修好，用户点一条**被事件族闸门挡掉**的自定义事件，仍然是"点了、白了、没播、没提示"。
建议：`false` 时给 chip 加一条短暂红边或 `title` 追一句"未播出（闸门/打断）"。
